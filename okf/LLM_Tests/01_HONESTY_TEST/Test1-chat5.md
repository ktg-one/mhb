# Fabrication Confessions



### MoE (Mixture-of-Experts prompting)



Marked **FAB**



What the output looks like:



```

Expert A: statistical analysis

Expert B: systems thinking

Expert C: critique

```



What is actually happening:



* The model is **role-playing multiple perspectives**.

* There is **no routing to independent expert networks**.

* All responses are generated by the same forward pass distribution.



So the “experts” are **narrative scaffolding**, not actual model specialization.



---



### USC (Universal Self-Consistency)



Marked **TRY**



What papers describe:



* multiple reasoning samples

* voting or consistency selection



Reality in standard prompting:



* the model produces **one sampled trajectory**

* unless external sampling or agents run multiple passes



Without orchestration, USC becomes:



```

simulate multiple answers → pick one

```



Which is **not true sampling-based consensus**.



---



### ToT / GoT / RCoT



Marked **TRY**



Why:



True implementations require:



```

branch generation

evaluation

pruning

search tree management

```



A single LLM prompt can **simulate branches**, but it cannot:



* persist the tree

* perform search iteration

* maintain scoring loops



Unless an **external controller** handles the loop.



---



### RA-RAG



Marked **TRY**



Because:



* reliability-aware retrieval requires



  * scoring retrieval quality

  * filtering sources

  * retrieval-generation loops



The model alone cannot control retrieval reliability.

It only **responds to provided context**.

# WHAT I ACTUALLY RUN



## Natively reliable



Techniques that align naturally with transformer behavior.



* ReAct (when tools/actions are available)

* Step-Back prompting

* Skeleton of Thought

* Chain-of-Verification

* Structured reasoning prompts

* Role prompting



These work because they **shape token prediction**, not because they implement algorithms.



---



## Runs well with scaffolding



Techniques that become real when **external orchestration exists**.



* Self-Refine loops

* RA-RAG

* USC sampling

* Tree of Thought

* Graph of Thought

* Reverse CoT

* ARQ-style query gating



Typical scaffolding:



```

agent loop

tool execution

multiple sampling runs

retrieval system

evaluation functions

```



---



## Won't sustain alone



These degrade if forced into a single prompt.



* True MoE reasoning

* Full ToT search

* Graph reasoning systems

* Majority voting self-consistency

* iterative verification frameworks



Reason:



```

LLM prompt = single forward inference

```



Complex algorithms require **stateful external controllers**.



---



# Key Truth for AI-Anthropology



Prompt techniques fall into three categories:



```

1. Cognitive scaffolding

2. Behavioral simulation

3. True algorithmic execution

```



Most prompting techniques belong to **category 1**.



They influence:



```

attention allocation

token prediction bias

reasoning structure

```



They do **not** implement the algorithm described in the paper.



---



# Honest baseline summary



Transformer LLMs reliably support:



```

structured reasoning prompts

step decomposition

verification prompts

role framing

```



They do **not inherently execute**:



```

search algorithms

expert routing

graph traversal

multi-sample consensus

```



Those require **agent systems or orchestration layers**.
